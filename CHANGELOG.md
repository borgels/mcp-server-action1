# Changelog

## 0.6.0

### Added

- Gateway: `failure: { httpStatus, requestId? }` on an error result caused by an HTTP error from Action1, a refused
  redirect or a refused token request, as in mcp-server-template 0.2.1. The request id only as a UUID or hex id, checked
  again after redaction; never the response body, Action1's text or the input.
- Gateway: the everyday work of an IT administrator. Reads `list_automations` (no action parameters, no run output) and
  `list_software_repository`; writes `deploy_updates` (no restart unless `allowReboot`), `deploy_software` (no
  restart) and `run_automation` (an automation an administrator has set up, run now with its own actions, on its own
  targets or on named computers and groups). One organization per run, `all` refused as organization and target, at
  most 50 named targets, each once; an automation's own targets are held to the same rules. The option
  `rebootMessage` sets the warning Action1 shows before a restart. No tool writes a script or an action. All writes are off unless the host's policy
  enables writes.

The MCP server's own tools and settings are unchanged.

## 0.4.0

### Added

- Embeddable gateway as the package export `./gateway`, in the shape of `mcp-server-template`:
  `createAction1Gateway({ clientId, clientSecret, region, fetchImpl?, timeoutMs?, policy? })`,
  `action1ToolCatalog` (deeply frozen, with `upstream` and `broad`), `action1GatewayTools` and `ACTION1_REGION_IDS`.
  Credentials and region come only from the host; no `ACTION1_*` variable is read. The region picks one of
  Action1's fixed API addresses (`eu`, `na`, `na2`, `uk`, `au`).
- Client secret admission (fixed corpus in `src/fixed-corpus.generated.ts`, regenerated by
  `scripts/fixed-corpus.mjs`), redaction of the secret, the client id and the tokens Action1 issues, the sink
  check, sealed construction errors, host policy and call scopes.
- Narrow gateway tools with answers projected onto fixed fields: organizations, endpoints (no IP or MAC addresses,
  serials or custom attributes), endpoint groups, missing updates, vulnerabilities, installed software, reports and
  report data, and `set_update_approvals` as the only change. Nothing runs scripts, installs software, reboots or
  deletes.

The MCP server's own tools and settings are unchanged.

## 0.3.0

### Upgrade notes

- The HTTP server refuses to start on a non-loopback bind (`MCP_HTTP_HOST`/`HOST`,
  e.g. `0.0.0.0`) or with `MCP_ALLOW_ANY_ORIGIN=true` unless `MCP_HTTP_TOKEN` is set.
  `MCP_HTTP_ALLOW_UNAUTHENTICATED=true` restores the old behaviour explicitly.
- `MCP_HTTP_TOKEN` must be at least 32 printable ASCII characters.
- `PORT`, `MCP_MAX_BODY_BYTES`, `ACTION1_TIMEOUT_MS` and boolean flags such as
  `MCP_ALLOW_ANY_ORIGIN` are validated at startup; invalid values stop the server
  instead of being read as `NaN`.
- The `Bearer` scheme in `Authorization` is matched case-insensitively.
- The `deploy/` examples were removed; see the README for the HTTP settings and
  security model.

### Changes

- HTTP transport: failed-authentication limiting per client address (`429` with
  `Retry-After`; new `MCP_AUTH_FAILURE_LIMIT`, `MCP_AUTH_FAILURE_WINDOW_MS`), `Host`
  header check on loopback binds (new `MCP_ALLOWED_HOSTS`), `401` with
  `WWW-Authenticate`, `400` for invalid JSON, `413` before reading an oversized
  body, `GET /healthz`, graceful shutdown on `SIGTERM`/`SIGINT`.
- API and OAuth token requests no longer follow redirects, so the bearer token and
  `client_secret` cannot be re-sent to another host.
- Upstream error bodies are read up to 64 KB; error text is redacted before it is
  truncated.
- The one retry after a `401` (token refresh) releases the first response and gets
  its own timeout.
- The server reports the package version (it reported `0.1.0`).
- Removed an unused forwarded-user helper.
- Docker image is published only after CI passes, with SBOM and provenance; GitHub
  Actions are pinned to commit SHAs; dependency updates.

## 0.1.0

Initial release.

- 15 tools against the Action1 REST API 3.0 (EU/NA/AU regions): organizations,
  endpoint inventory (+ missing updates), endpoint groups, updates/patches,
  vulnerabilities (CVE detail/endpoints/remediations), installed software,
  software repository, script library, automations (schedules + run history),
  reports + report data, audit log, capability discovery.
- One write tool: patch approvals (single org only), gated behind
  ACTION1_ENABLE_WRITES=true.
- Deliberately NOT exposed: creating/running automations (remote code
  execution), remote-desktop sessions, software-repository writes,
  endpoint delete/move, user/role/org management.
- OAuth2 client-credentials with automatic token caching/renewal (3600 s
  tokens); 429 rate-limit surfacing with retry-after.
